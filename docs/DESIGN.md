# Design

How forhunt-viewer is built, and the targets it is measured against
(numbers in [PERF.md](PERF.md), decisions and their reasons in
[DECISIONS.md](DECISIONS.md)).

## Principles (from the brief, condensed)

1. Performance first, measured: every claim has a command, an input and a machine in docs/PERF.md.
2. The UI never blocks: indexing, filtering, sorting and export run on worker threads, with progress and cancel.
3. Bounded memory: index once, read only what is displayed. The index is a small fraction of the file size.
4. Forensically sound: inputs are opened read-only. Caches and sessions live in OS dirs or a user-chosen location, never next to the evidence.
5. Robust: malformed CSV never crashes the app. Bad rows are counted and can be viewed.
6. Deterministic: same input and filters always give the same rows in the same order.
7. Clean-room: workflows only. No code, assets or name from Timeline Explorer or any other project. Permissive dependency licences only (`cargo deny`).
8. No real evidence in the repo: test data is generated by `tools/csv-gen` (seeded).

## Engine design (starting point, validated by measurement)

*This section is the starting design; the measurements changed parts of it:
positional reads replaced the mapping (D-008), see DECISIONS.md.*

**Access.** The engine memory-maps the file read-only (`memmap2`) and uses the
mapping for random row access and the parallel scans. Positional reads are
measured against it. RSS under mmap counts page cache that the kernel can drop,
so we report both RSS and private (anonymous) memory. Decision: D-00x in
DECISIONS.md.

**Dialect.** The first 1 MiB is sniffed for:
- the encoding, from the BOM (UTF-8, UTF-16LE/BE) and NUL patterns;
- the delimiter (`,` `;` tab `|`), chosen by the most consistent field count across sampled lines;
- the quote char (`"`, else none);
- whether the first row is a header;
- the line ending.

UTF-16 is transcoded once to a cached UTF-8 copy in the cache dir. It is also
measured against decoding on the fly. Invalid UTF-8 is shown lossily, and the
stored bytes are never altered.

**Row index.**
- Rows are found by a parallel, quote-aware pass. The file is cut into chunks
  (around 8 MiB).
- Each chunk runs a small CSV state machine (FieldStart / Unquoted / Quoted /
  QuoteInQuoted) from every possible entry state at once. The state vectors
  converge after the first few bytes, and a sequential fix-up picks the right
  run per chunk.
- A quote is special only at the start of a field, like common CSV readers. A
  stray quote inside an unquoted field is therefore literal and cannot swallow
  the rest of the file.
- Pathological records are re-split at raw newlines and flagged bad. A record
  is pathological when an unterminated quote runs past a cap (16 MiB, D-00x).
- Field counts are checked in the same pass. Rows whose count differs from the
  header are recorded in a "bad rows" bitmap.
- Offsets: one `u64` base per 1024-row block plus a `u32` delta per row
  (4 B/row). A block that would overflow `u32` stores absolute `u64` offsets.
- First rows: the head of the file is parsed directly and shown before the full
  index is done.

**Column indexes.** These are built by a second parallel pass over row ranges.
It reads from page cache; fusing it with pass 1 is a measured option.
- *Dictionary columns* (low cardinality, auto-detected, cap ~64k distinct
  values per column, abandoned when exceeded): each value maps to a roaring
  bitmap of rows plus a count. **Any** predicate on a dictionary column runs
  once per distinct value, then the bitmaps are OR-ed. "in / not in", contains,
  equals, `>`... are therefore all instant there, and the value-list dropdown is
  free.
- *Time columns* (detected on a sample: ISO 8601, `yyyy-MM-dd HH:mm:ss.fffffff`,
  with or without offset, `T`/space, US/EU `M/d/yyyy`, `d/M/yyyy`...): parsed to
  `i64` 100 ns ticks (forhunt's unit), plus a sorted permutation. When the file
  is already sorted, the permutation is skipped (identity flag).
- *Numeric columns*: a flag plus min/max. Comparisons on non-dictionary numeric
  columns are parallel scans with parsing.
- *High-cardinality text*: no index. Filters run as a parallel scan. Raw-byte
  search (`memchr::memmem`, or a case-insensitive `regex` prefilter) finds
  candidates, then the decoded cell is verified exactly. Results are cached as
  bitmaps.

**Filter engine.**
- A filter is an expression tree (AND/OR/NOT) of column predicates:
  - equals, not equals, contains, not contains, begins with, ends with;
  - blank, not blank, in, not in, regex;
  - `>`, `>=`, `<`, `<=`, between (for numbers and dates);
  - plus a global "any column contains".
- Each leaf evaluates to a cached `RoaringBitmap`, and the tree is combined with
  bitmap algebra.
- Text matching is case-insensitive by default, with an option to make it
  case-sensitive.
- Property tests check the result against a naive row-by-row evaluator.

**Sort.**
- The output is a permutation of the filtered rows: multi-column, parallel, and
  stable, with row number as the final key (deterministic).
- Time columns walk the precomputed permutation. Dictionary columns walk values
  in order and intersect.
- Other columns sort by `(key prefix u64, row)` and resolve ties by comparing
  the full cell from the mapping.

**Index cache.**
- Key: canonical path + size + mtime + BLAKE3 of sampled blocks (first / middle
  / last 64 KiB).
- Stored in the OS cache dir (`directories` crate) as a versioned binary file
  holding the row offsets, bad rows, dialect, column indexes and time
  permutation.
- The cache is invalidated when any part of the key changes.

**Robustness.** Every row read is bounded. Cell rendering truncates huge cells
for the grid and shows them in full in the detail pane on demand. No panics:
fallible paths return errors, and worker threads run under `catch_unwind` with
the error shown in the UI.

## GUI (egui/eframe)

- **Grid.** A custom virtual grid, not `TableBuilder`. 100 M rows x 20 px is
  2e9 px, beyond f32 precision, so the scroll position is kept as a row index
  (`f64`) and only visible rows are fetched and painted. A cache holds the
  decoded visible rows; the custom scrollbar maps to the row index.
  Phase 1 spike: 100 M synthetic rows at 60 fps, measured as frame CPU time.
- **Header filter row.**
  - Operator picker and value-list dropdown (checkboxes, counts, search).
  - Filter chips and "clear all".
- **Global search.** Ctrl+F, highlight, next/prev.
- **Columns.** Chooser (show/hide, drag reorder), resize, freeze first N columns.
- **Sorting.** Click a header to sort, shift-click to add a secondary key.
- **Detail pane.** Key/value view; JSON cells pretty-printed; copy cell, row or
  column.
- **Tags.** A checkbox column and per-row notes; filter on tagged rows.
- **Status bar.** Shown/total rows, filter time, bad rows, encoding, index
  progress.
- **Files and sessions.**
  - Export filtered or tagged rows as CSV or JSONL.
  - Save and restore sessions as JSON.
  - Tabs, drag-and-drop, recent files.
- **Display and input.** Display time-zone conversion; keyboard shortcuts
  (Ctrl+F, Ctrl+G, arrows, Ctrl+C); dark and light themes.
- **forhunt integration.** Detect `ForhuntId`; copy
  `forhunt show <id> -p <evidence>`; export tagged ids.

## OS integration

- **CLI.** `forhunt-viewer [FILE...]`; single instance optional (later).
- **macOS.** Apple Silicon (arm64) `.app` only (D-018). Info.plist
  `CFBundleDocumentTypes` (`public.comma-separated-values-text`,
  `public.tab-separated-values-text`, `LSHandlerRank=Alternate`). `.dmg` built
  with `hdiutil`. Unsigned (user decision): README documents right-click > Open.
- **Windows.**
  - MSI that registers `OpenWithProgids` for .csv/.tsv; it is never the default
    handler.
  - Portable .zip.
  - Unsigned (user decision).
- **Linux.**
  - AppImage and .tar.gz.
  - A .desktop file with `MimeType=text/csv;text/tab-separated-values;`, plus an
    icon.
- **Homebrew.** Cask `forhunt-viewer` in `0xRD/homebrew-tap`, bumped by
  `scripts/release-macos-local.sh` (D-032).

## Quality, CI, release

- **CI** on Linux, macOS and Windows:
  - fmt, clippy `-D warnings`, tests, `cargo deny`;
  - benches compile;
  - a perf gate that counts instructions (callgrind) for headless engine
    benchmarks, head vs base, built in the same job. The corpus is verified by
    size and row count before measuring.
- **Tests.**
  - Engine unit tests.
  - Proptest: index vs reference parser, filters vs naive evaluation.
  - Golden files for generated edge cases.
  - UI smoke tests with `egui_kittest`.
- **Release on tag** (or a manual dispatch with a tag, see forhunt B-005):
  - arm64 .dmg (D-018);
  - .msi and .zip;
  - AppImage and .tar.gz;
  - a `.sha256` for each.


## Acceptance targets and how they are measured

These targets apply to a 5 GB / ~20 M row file from `csv-gen forhunt`. The
build container has 4 cores and no guaranteed NVMe, so numbers are reported
for this machine with its specs. The brief's 8-core NVMe target is
extrapolated only with a recorded rationale.

| Target | Measure |
|---|---|
| First screen < 1 s | `fhv-bench open --first-rows` timer: open, dialect, first 100 rows decoded |
| Full index, I/O bound | Index time vs `cat file > /dev/null` (cold and warm cache) |
| Reopen with cache < 1 s | Second `open` with the cache present |
| In/not-in < 100 ms | Engine bench on `EventId`/`Channel` |
| Contains on one text column < 2 s, then cached | Engine bench, cold and second run |
| Global search | Engine bench, reported |
| Time sort instant; arbitrary column sort < 3 s | Engine bench |
| 60 fps scrolling | App frame CPU time (p50/p99) on scripted scrolling |
| Peak memory | `/usr/bin/time -v` max RSS, plus private memory from `/proc/self/smaps_rollup` |
