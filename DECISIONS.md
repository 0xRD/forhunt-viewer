# Decisions

Every ambiguous point resolved during the build: what, why, and the measured
evidence where there is some. Newest last.

| # | Decision | Reason / evidence |
|---|----------|-------------------|
| D-001 | No Apple Developer ID, no Windows code-signing certificate: macOS .dmg and Windows .msi/.zip ship unsigned. README documents right-click > Open (macOS) and the SmartScreen "More info > Run anyway" (Windows). | User decision (2026-10-22). Recorded as B-001/B-002 so signing can be added when credentials exist. |
| D-002 | Homebrew cask: template written now, published after v0.1.0. | User decision (2026-10-22); needs a tap token (B-003). |
| D-003 | Crates are `fhv-engine` (lib), `fhv-app` (bin `forhunt-viewer`), `csv-gen` (tool), edition 2024, licence `MIT OR Apache-2.0`. | Brief. Prefixed names avoid clashes on crates.io and with std crate names. |
| D-004 | Subagents: research/review on Sonnet, mechanical tasks on Haiku; the engine core stays on the main agent; no Opus subagents. | User instruction (cost). |
| D-005 | GUI stack: egui/eframe 0.37 with the `glow` (OpenGL) backend and a custom virtual grid (not `egui_extras::TableBuilder`, not a `ScrollArea`). The vertical position is an `f64` row index; only visible rows are fetched (`GridSource::prepare`) and painted; own scrollbar. Slint/iced not evaluated further. | Spike (docs/PERF.md, "Phase 1"): 100 M and 1 B synthetic rows scroll with UI-logic time p50 0.68 ms / p99 8.2 ms and total frame CPU (incl. software OpenGL rendering on llvmpipe) p50 6.5 ms / p99 15.2 ms, under the 16.7 ms budget of 60 fps even without a GPU. f32 coordinates cannot address 2e9 px (100 M x 20 px), hence the row-index scroll. `glow` over `wgpu`: smaller binary, faster build, and runs on the same OpenGL 3.3 stack as the CI and VM machines; revisit if a platform needs wgpu. |
| D-006 | Fonts: Inter (UI) and JetBrains Mono (grid), both SIL OFL 1.1, bundled from unmodified upstream TTFs (font name tables checked: "Inter 4.001", "JetBrains Mono 2.211"; copies taken from the crates.io packages `shadcn-egui-font-inter` / `-jetbrains-mono` 0.6.0 because GitHub downloads are blocked in the build container); licences in `crates/fhv-app/assets/fonts/`. egui's `default_fonts` feature is disabled. | `epaint_default_fonts` is `(MIT OR Apache-2.0) AND OFL-1.1 AND Ubuntu-font-1.0`; the Ubuntu Font Licence is outside the permitted list (brief: OFL for fonts). |
| D-007 | `cargo deny` ignores RUSTSEC-2026-0370/0371/0372 (`zvariant`, `zbus_names`, `zvariant_derive` "unmaintained"). | These crates were merged into `zbus`; the advisories flag the standalone crates as unmaintained, with no vulnerability. They come from accesskit's Linux screen-reader bridge (via eframe). Accessibility is worth keeping; revisit when accesskit moves to the merged zbus. |
| D-008 | File access: positional reads (`pread` / `seek_read`) by default; mmap stays available as an option (`Access::Mmap`). | Measured (docs/PERF.md, phase 2): indexing 5 GiB, warm, is the same speed with both (1.3-1.9 s). Cold, pread is faster (2.6 s vs 3.3-3.5 s; `cat` takes 2.4 s). Peak RSS is 80-124 MiB with pread vs 5.2 GiB with mmap, because every touched page of the mapping counts as resident. Analysts read RSS in Task Manager / Activity Monitor as "memory used". pread also avoids SIGBUS if the file is truncated while open. Same finding as forhunt D-021. |
| D-009 | Row index: a parallel pass over 8 MiB chunks. Each chunk runs the four possible entry states at once, packed in one byte. Specials (delimiter, quote, `\n`) are found 8 bytes at a time with SWAR; one "other" transition is applied per gap (it is idempotent). A sequential fix-up picks the right run per chunk. The first window is a single chunk, so rows show immediately. | Correct for any chunk boundary (proptest at chunk sizes 1..63 vs an independent reference reader). The byte-at-a-time table walk ran at ~330 MB/s per core (dependent loads); the SWAR skip doubled throughput (1.3 GB/s -> 2.9-4.3 GB/s on 4 cores, warm). |
| D-010 | CSV semantics: a quote opens a quoted field only at a field start, so stray quotes are literal. Text after a closing quote is kept. Blank lines (empty or lone `\r`) are skipped. Trailing `\r` is dropped. A record over 16 MiB is cut back into its physical lines, which are flagged bad. A last row that ends inside an open quote is flagged bad. | Lenient like the common CSV readers; robustness principle 5: one stray quote must not turn a 5 GB file into one row. 16 MiB leaves room for 1 MiB cells (brief) and multi-line payloads. |
| D-011 | Encodings: BOM-less UTF-16 is detected from the NUL pattern. A file that is not valid UTF-8 and has no valid multi-byte sequence in the first MiB is read as Windows-1252. Files with mixed valid and invalid UTF-8 are shown as UTF-8 with U+FFFD for bad bytes. UTF-16 and Windows-1252 are transcoded once to a UTF-8 copy in the cache dir; the original is never touched. The grid shows rows after transcoding. | One code path for everything downstream (index, filters, export) at UTF-8 speed. Transcoding is a one-off sequential pass, and multi-GB UTF-16 CSVs are rare in DFIR tool output. The copy needs disk space equal to ~half to all of the original; this is noted in the README. |
| D-012 | Case-insensitive text operators (equals, contains, begins/ends with, in) are defined by the `regex` crate's simple Unicode case folding: the engine matches them with a case-insensitive regex. Range operators on text compare lowercase strings. | The block prefilter is a case-insensitive regex over raw bytes. Matching cells with the same folding rules makes the prefilter a guaranteed superset; `to_lowercase` can disagree, e.g. `İ` lowercases to `i̇`. Literals with a quote or newline skip the prefilter: they may be spelled `""` in the file, or hide an overlapping match in the next row. |
| D-013 | Sort keys: text uses a 24-byte inline key. Ties are resolved by successive 24-byte windows read through a transient read-only memory map, then a full compare of small groups. Measured cost: a full sort of a long, shared-prefix, nearly unique text column over 20 M rows takes ~11-12 s (target 3 s not met). The same sort on a filtered 1 M-row view takes 0.8 s. Time, dictionary and number sorts are within target (0.02-2.2 s). | Bounded memory: no full copy of the column (Details would need ~2.4 GB). Tried and measured slower: per-row pread (32.6 s) and a comparison sort of borrowed cells (26.8 s). While text ties are resolved, peak RSS includes the mapped file pages (file-backed, reclaimable). The UI runs sorts in the background with progress and cancel, so a long sort never blocks. Revisit with a column-at-a-time extraction to a temp file if analysts need it. |
| D-014 | Acceptance corpora: `hayabusa` layout, 5 GiB = 20.3 M rows (the brief's 5 GB / ~20 M shape), and `forhunt` layout, 5 GiB = 8.7 M rows (realistic EvtxECmd-width rows, ~620 B each). | The forhunt/EvtxECmd layout is ~620 B/row, so 5 GB is 8.7 M rows. Measuring both covers the row-count-bound and the byte-bound cases. |
| D-015 | Column profiling uses a sample (the first 10 k rows plus 64 slices spread over the file). Dictionary candidates have ≤ 512 distinct values in the sample, and the dictionary is abandoned past 65 536 values in the full pass. A time column needs ≥ 90 % of its non-blank sampled cells to parse; a number column ≥ 99 %. The primary time column is the first with a known name (TimeCreated, Timestamp, ...) or else the first time column; only it gets per-row ticks (8 B/row) and a sort permutation (4 B/row, skipped when the file is already in time order). | Per-row ticks for every time column (MFTECmd has 8) would cost 64 B/row. Other time columns are filtered and sorted by parsing during a scan. |
| D-016 | Rust toolchain pinned to 1.97.0 (rust-toolchain.toml and CI). | CI's `stable` moved to 1.99 mid-session and its new clippy lints (`chunks_exact_to_as_chunks`) failed `-D warnings` on code that was clean locally. Pinning makes local and CI checks identical; bump deliberately. |
| D-017 | CI runs only on manual dispatch (no push/PR trigger). Linux only by default; macOS + Windows behind an `all_os` input. Local gate before each push: `scripts/check.sh` (fmt, clippy -D warnings, all tests) plus `scripts/check-gen.sh`. CI is dispatched at milestones and before a release; the release workflow will run on the version tag only. | Owner request: GitHub Actions minutes are nearly used up for the month. macOS minutes count 10x and Windows 2x. |
| D-018 | macOS release: Apple Silicon (arm64) only; no x86_64 / universal binary. | Owner request: Intel Macs are not needed. Halves the macOS build minutes. Supersedes the "universal" item in PLAN.md. |
| D-019 | No `directories` crate: config/cache paths are computed by hand (XDG on Linux, ~/Library on macOS, %APPDATA%/%LOCALAPPDATA% on Windows). | `directories` -> `dirs-sys` -> `option-ext` is MPL-2.0 (copyleft), outside the licence policy; the logic is ~25 lines. |
| D-020 | Fonts: missing glyphs draw a box (tofu) instead of failing, and eframe's `system_fonts` fallback is on, so CJK / Arabic / other scripts in data render with the OS fonts. UI strings use only glyphs present in Inter / JetBrains Mono. UI tests run with egui_kittest's panic-on-missing-glyph policy to keep it that way. | The first UI smoke test caught a panic on `⏳` (not in the bundled fonts). Data can contain any character, and a viewer must never crash on it. |
| D-021 | Filter UI model: each column holds a quick "contains" box (in the filter row) plus a list of conditions combined with "match all" (AND) or "match any" (OR). The value list (dictionary columns) writes one `in` or `not in` condition, whichever list is shorter. Columns are ANDed. Global search can highlight only or also filter. "Tagged only" and "bad rows only" are extra AND terms. | Covers the Excel/TLE-style workflow and AND/OR/NOT groups (negated operators give NOT) without a free-form expression editor in the MVP. The engine already takes arbitrary trees; a tree editor can come later. |
| D-022 | Tagged-ID export for the forhunt skill: a text file with one `ForhuntId` per line, followed by a TAB and the note when there is one. `Copy forhunt show command` uses the evidence path set in the forhunt menu (placeholder `<evidence>` until set). | The forhunt skill has no import format. One id per line works with `cut -f1` / `xargs forhunt show`, and the note stays readable. |
| D-023 | No single-instance forwarding (a second launch opens a second window). | Optional in the brief. It needs per-OS IPC; drag-and-drop and File > Open cover adding files to a running window. |
| D-024 | Queries and searches start after 250 ms without input. A query or search superseded by newer input is cancelled. | Found when driving the release build: every keystroke queued a full scan of 5 GB. |
| D-025 | Packaging. Windows: MSI built with WiX v5 (`wix` dotnet tool, pinned 5.0.2), per-machine, `OpenWithProgids` for .csv/.tsv/.txt, plus a portable zip; static CRT. Linux: built on ubuntu-22.04 (glibc 2.35 floor); tarball with a .desktop file, and an AppImage via appimagetool's `continuous` release. macOS: arm64 `.app` ad-hoc signed (`codesign -s -`), in a UDZO .dmg; Info.plist declares CSV/TSV with `LSHandlerRank=Alternate`. | WiX is the standard MSI toolchain. v5 avoids v6's maintenance-fee EULA step and is a build tool only (not shipped). appimagetool publishes no stable versioned binary we can pin from this environment (GitHub downloads are blocked here); it only builds the package. Apple Silicon binaries must carry at least an ad-hoc signature to run. |
| D-026 | macOS "Open With" / double-click: `application:openURLs:` is added to `NSObject` at the start of `main` (objc runtime `class_addMethod`); winit's own delegate inherits it and the paths are queued for the next frame (crates/fhv-app/src/macos.rs). | Finder delivers documents to the app delegate, not argv. winit 0.30.13 installs its own `WinitApplicationDelegate` and casts `NSApp.delegate` back to it, so the delegate must not be replaced (review R-018: the first version did). Adding the method before the event loop starts also covers launch-time documents. Type-checked for aarch64-apple-darwin; not run on a Mac (none in the build environment, B-004). |
| D-027 | `blake3` uses its pure-Rust implementation. | It hashes ~192 KiB per opened file (cache key), where speed is irrelevant. The C/assembly build broke cross-target checks and needs a C toolchain per target. |
| D-028 | Windows release builds use the GUI subsystem (no console window). `--help` / `--version` then print nothing when run from a console on Windows. | Double-clicking a CSV must not open a console window next to the viewer. |
| D-029 | CI perf gate: callgrind instruction counts (1 thread) of `fhv-bench index --no-cache` + `fhv-bench query` (bench/gate.ops) on a 40k-row forhunt-layout corpus checked by size and line count; head vs base built in the same job; fails above +3 %. | Same method as forhunt (D-017 there). Measured noise between two identical builds: +0.02 % (3 683 838 272 vs 3 682 970 059 instructions). Covers the row scan, column pass, dictionary / scan / time filters and three sort paths. |
| D-030 | Perf review fixes merged: memchr-based field splitting (`scan::field_end`) shared by `split_row_odd` / `nth_field` / `count_fields`; literal prefix prefilter for user regexes via regex-syntax, only when the literal set is finite and holds no empty / `"` / newline literal (else full scan); `Source::read` reuses its buffer without zero-filling. F4/F6 (column pass tuning, further experiments) deferred. | docs/PERF-REVIEW.md: regex without prefilter was the one remaining known miss (4.4 s -> 0.55 s on 5 GB); gate -22.75 % instructions. Prefilter safety: a match must contain one of the literals inside one physical block line, so literals spanning a quote or newline could miss rows; those patterns fall back to the full scan. Tested by proptest against naive evaluation. |
| D-031 | The macOS .dmg is built and uploaded from the owner's Mac (`scripts/release-macos-local.sh vX.Y.Z`) after the tag's Release run publishes the Linux and Windows files; the workflow's macOS job runs only on a manual run with `macos: true`. | macOS runners cost 10x Actions minutes; the package was verified on a real Mac (2026-10-24), which the runner never did (no GUI). |
| D-032 | The Homebrew cask lives in `0xRD/homebrew-tap` (`Casks/forhunt-viewer.rb`, source of truth; the template in `packaging/homebrew/` is removed). `scripts/release-macos-local.sh` bumps its version and sha256 after uploading the .dmg. The cask keeps the quarantine flag and explains Open Anyway in its caveats, like Hector's. Supersedes D-002. | The .dmg is built locally (D-031), so the local script, using the owner's `gh` login, is where the checksum is known; no deploy key needed. Stripping quarantine in a postflight would hide Gatekeeper from users. |
| D-033 | EVTX, `$MFT`, `$J` and folders open directly: `forhunt_core::input::open_all` + `forhunt_output::export::write_all` (git dependency pinned to a forhunt release tag; bump `FORHUNT_VERSION` in convert.rs with it) write the CSV of `forhunt parse -F csv` to `cache/forhunt/<key>/<name>.csv`, which opens as a normal tab sorted by TimeCreated. Key = blake3(forhunt version, each source's file key and path). Inputs picked or dropped together make one timeline. The evidence path for `forhunt show` is set automatically. Finder/Windows "Open with" list .evtx (and folders on macOS). | No duplicated parser or CSV layout: same bytes as the CLI, so ForhuntIds stay valid. Converting to CSV reuses the whole engine (index cache, filters, sort, export) instead of a second table model. Cache, not next to the evidence (read-only evidence). |
| D-034 | Time filters: an inclusive upper bound (`<=`, the end of `between`) covers the whole period its operand names at the precision written: a date is the whole day, `HH:mm` the whole minute, `HH:mm:ss` the whole second, k fraction digits 10^-k s. `>=`, `>` and `<` start at the operand's first tick (as before). Full-precision operands (7 digits, e.g. a value copied from a cell) behave exactly as before. | Lab QA (2025-10-24): on 56,930 real events of one day, `TimeCreated between 2025-10-21 and 2025-10-21` returned 0 rows and `<= 2025-10-21 13:08:19` dropped the 212 events inside that second (cells carry 100 ns fractions). A filter must not return nothing where an analyst expects the day. `>` keeps the Excel reading (`> 13:08:19` includes 13:08:19.5), so `> x` and `<= x` can overlap for a coarse x: overlap shows a row twice across two filters, never hides one. |
| D-035 | The value list and the cell menu's "= / ≠ this value" write a separate per-column selection (`ColFilter::values`: `in` / `not in`) that is always matched exactly (case and spaces count), whatever the column's case-sensitivity box says, and is ANDed with the column's other conditions. The condition editor's own `in list` / `not in list` keep the column's case setting (pasted IOC lists stay case-insensitive by default). Sessions store the selection in a new optional `values` field (older sessions load unchanged). Supersedes the value-list part of D-021. | Lab QA (2025-10-24): the list shows `Admin`, `admin` and `ADMIN` as separate entries, but its `in` / `not in` condition was case-insensitive by default, so ticking `admin` showed all three and unticking `ADMIN` (a `not in` list) hid all three; "≠ this value" on `admin` also hid `Admin` / `ADMIN` rows. |
| D-036 | On a time column, `>` `>=` `<` `<=` and between need operands that parse as date-times (ISO 8601 or the column's own day/month order); anything else is an error shown in the status bar, checked for every predicate before evaluation. Number and text columns keep the number / text fallback. Global search (any column) still compares time columns as text for such operands. | Lab QA (2025-10-24): `TimeCreated >= 2025` matched nothing without a word (the operand fell back to a number and time cells are not numbers), and `21/10/2025` on a month-first column fell back to a text comparison. An error the analyst can fix is better than an empty or wrong timeline. |
