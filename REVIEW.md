# Fresh-eyes review of forhunt-viewer (master @ 6dc71ab)

Scope: every file listed in the brief was opened and read (docs, engine, app, tools, scripts, workflows, packaging).
Nothing under the repo was changed except this file. Verification used:
- `scripts/check.sh` (fmt, clippy -D warnings, tests): passes.
- A scratch random-input fuzzer over the engine (20 000 inputs: ragged rows, stray quotes, NUL, invalid UTF-8, UTF-16, CRLF, BOM; every operator on every column, global search, multi-key sorts, CSV/JSONL export): 0 panics, 0 unexpected errors.
- Scratch kittest UI tests, run in a copy of the tree under /tmp (not in the repo).
- Hand-built engine cases and large generated files (all under /tmp/claude-0/review, deleted afterwards).

Legend: **verified** = reproduced by running; **by reading** = reasoning from code, not run; **unverified** = depends on a platform or tool I could not run here.

## Things checked and found correct (no action)

- Row-index chunk fix-up, SWAR scan, wide blocks (> 4 GiB per 1024 rows) and `bad` ranges; blank-line skipping keeps ranges consistent; header detection with a leading blank line; BOM, CRLF, quoted CRLF, UTF-16 with surrogates cut at block ends.
- Row numbers: `columns::build` rejects > u32 rows with a clear error; tags are keyed by file row, so sorting/filtering does not move them.
- Cache: BLAKE3 check, section bounds checks, key includes size/mtime/options; a corrupted file is ignored.
- Sort: ties by row number, desc handled per key, window/refine logic consistent with `text_cmp`.
- Time parsing/format: no overflow for years 0000-9999; DST conversion test.
- `cargo tree`: no unexpected licences; fonts excluded from egui defaults as documented.

Build artefacts note: my scratch UI tests were compiled with `CARGO_TARGET_DIR` pointing at the repo's `target/` (ignored by git); no tracked file changed.
